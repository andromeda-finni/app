# Сервер и работа приложения с сетью

## Адрес сервера

Мобильное приложение «Грошик» (APK) обменивается данными с сервером по адресу
**https://groshiktheapp.ru**.

- Соединение только по **HTTPS**. Release-сборка отказывается отправлять запросы
  на удалённый адрес по обычному HTTP, чтобы токен входа ребёнка не передавался
  по сети в открытом виде.
- Адрес задаётся при сборке APK: GitHub Actions передаёт его в сборку из
  переменной репозитория `API_BASE_URL` (`--dart-define=API_BASE_URL=…`).
  Release APK из GitHub Releases собран с `https://groshiktheapp.ru`.
- Проверка, что сервер работает: https://groshiktheapp.ru/health
  возвращает `{"ok":true,...}`.

На сервер отправляются только игровые данные: имя питомца, выбранная
сложность, бюджет, покупки, копилка, прогресс заданий и привязка к родителю.
Персональные данные ребёнка (имя, возраст, телефон, почта, местоположение)
приложение не собирает. Вход анонимный: сервер выдаёт случайный токен и хранит
только его хэш.

## Первый запуск: нужен интернет

**При первом запуске после установки телефон должен быть подключён к
интернету.** Без сети приложение не сможет начать игру и попросит проверить
подключение.

Зачем нужна сеть в первый раз:

1. **Создание профиля ребёнка.** Сервер регистрирует новый профиль и выдаёт
   токен входа. Без него телефону не с чем связать прогресс: его нельзя будет
   сохранить, перенести и показать родителю.
2. **Сохранение питомца и первого дня.** Имя и облик питомца, выбранная
   сложность и учебный бюджет из знакомства (10 монет) записываются на сервер.
   Из этого бюджета сервер открывает первый игровой день.
3. **Загрузка игровых каталогов.** Цены и свойства товаров магазина, артефакты
   для мечты, правила экономики (доход дня, резерв на еду, Сундук Морозко),
   просьбы персонажей на карте хранятся на сервере и могут обновляться без
   выпуска нового APK. При первом входе приложение получает их и сохраняет на
   телефоне.
4. **Честная экономика.** Монеты, покупки и награды рассчитывает сервер: он
   проверяет ответы в заданиях и не даёт начислить монеты дважды. Поэтому
   стартовый баланс и правила должны прийти именно с сервера.

## После первого запуска: можно играть без интернета

После первого входа приложение работает и без сети (offline-first). Последнее
состояние игры сохраняется на телефоне, а действия без сети складываются в
очередь.

Без интернета доступны:

- просмотр всех разделов: дом, питомец, магазин, копилка, карта;
- новый игровой день, план бюджета, покупки, перевод в копилку и обратно,
  завершение дня;
- уход за питомцем (поглаживание, еда, живая вода);
- Сундук Морозко, страховка, артефакты (надеть, починить), получение мечты,
  парк;
- просьбы дня, которые были загружены, пока была сеть: монеты за выполненное
  задание начисляются сразу.

Нужна сеть:

- регистрация и знакомство при первом запуске;
- выбор просьб на новый день, если день начат без сети (их выбирает сервер);
- случайные события питомца;
- привязка к родителю и экран родителя.

Вверху экрана в это время видна плашка «Играем без интернета. Всё сохранится и
отправится само, когда связь вернётся». Когда сеть появляется, приложение
отправляет действия на сервер по порядку, и сервер проверяет каждое по своим
правилам. Если что-то не прошло проверку (например, задание не засчитано),
ребёнок видит короткое пояснение, и баланс приводится к серверному.

## Устройство сервера

Сервер развёрнут на VPS (Ubuntu) в Docker Compose (`deploy/docker-compose.yml`):

| Сервис | Назначение |
|---|---|
| `caddy` | принимает HTTPS на портах 80/443 с сертификатом проекта и передаёт запросы backend |
| `backend` | API на Node.js/Fastify (образ собирается из `backend/Dockerfile`) |
| `db` | PostgreSQL 17; порт наружу не открыт, доступен только backend |
| `migrate` | разовый запуск миграций `db/migrations` и каталога `db/seed.sql` при каждом деплое |

Всё лежит в `/opt/groshik`. Секреты хранятся только на сервере и в репозиторий
не попадают:

- `/opt/groshik/.env`: пароли PostgreSQL, создаются `deploy/bootstrap.sh`;
- `/opt/groshik/certs/fullchain.pem` и `privkey.pem`: TLS-сертификат домена.

Backend подключается к базе под ограниченной ролью `groshik_app` без прав на
изменение схемы. Через прокси Caddy он видит настоящий IP каждого телефона
(`TRUST_PROXY_HOPS=1`), поэтому ограничение частоты запросов работает для
каждого устройства отдельно.

## CI/CD backend

Workflow `.github/workflows/deploy-backend.yml`:

1. Запускается после успешного `CI` на `main`, если в коммите менялись
   `backend/`, `db/` или `deploy/`. Можно запустить и вручную: Actions → Deploy
   backend → Run workflow.
2. Собирает Docker-образ backend.
3. Копирует образ, `deploy/` и `db/` на сервер по SSH (пользователь `deploy`).
4. На сервере `deploy/deploy.sh` загружает образ, применяет миграции и каталог,
   перезапускает backend и ждёт `/health`. Предыдущий образ остаётся для
   быстрого отката.
5. Проверяет снаружи, что https://groshiktheapp.ru/health отвечает `ok`.

Нужные секреты репозитория (Settings → Secrets and variables → Actions):
`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` и
переменная `API_BASE_URL=https://groshiktheapp.ru` для сборки APK.

### Первичная настройка сервера (один раз)

```bash
# ключ, которым GitHub Actions заходит на сервер
ssh-keygen -t ed25519 -f ~/.ssh/groshik-deploy -N "" -C github-deploy

# Docker, пользователь deploy, /opt/groshik и .env с паролями, файрвол
ssh root@groshiktheapp.ru "bash -s -- '$(cat ~/.ssh/groshik-deploy.pub)'" < deploy/bootstrap.sh

# сертификат: сертификат + цепочка УЦ в fullchain.pem, ключ в privkey.pem
scp fullchain.pem privkey.pem root@groshiktheapp.ru:/opt/groshik/certs/
ssh root@groshiktheapp.ru 'chown deploy:deploy /opt/groshik/certs/* && chmod 600 /opt/groshik/certs/privkey.pem'
```

### Полезные команды на сервере

```bash
cd /opt/groshik
docker compose ps                    # состояние сервисов
docker compose logs -f backend       # журнал API
docker compose restart caddy         # после замены сертификата
```

## Выпуск APK

Release APK публикуется в GitHub Releases автоматически при пуше тега `v*`
(`.github/workflows/release.yml`), например:

```bash
git tag v1.2.0 && git push origin v1.2.0
```

Сборка берёт адрес сервера из переменной `API_BASE_URL`. APK, собранный без
неё или с HTTP-адресом, workflow не выпустит.
