# Дневные просьбы: локальная реализация

## Контракт

- Источник дня — `game_periods`, не календарь и не часы устройства.
- Три разных персонажа; действующий бонус сапог даёт четыре места.
- Сапоги учитываются при формировании списка в начале игрового дня. Уже
  обещанное четвёртое место не исчезает, если сапоги затем износились или сняты.
  Новые сапоги дают дополнительное место со следующего игрового дня.
- Невыполненные просьбы (включая ещё не начатые) имеют приоритет на новом дне.
  Случайно заполняются только свободные места. Выбор сохраняется один раз.
- Внутри персонажа сохраняется порядок уровней; между персонажами очереди нет.
- Успех не заполняет освободившееся место новым заданием в тот же день.
- Все семь площадок используют исходный кирпичный овал `checkpoint_road.webp`
  с одинаковой геометрией во всех состояниях, по центрам овалов карты.
  «1» означает новую дневную просьбу, часы — начатую, галочка — выполненную
  сегодня. При отсутствии просьбы овал пуст. Если вся история персонажа пройдена,
  галочка сохраняется в следующих днях; при нажатии — «Ты уже помог, спасибо!».
- Повторное прохождение — без энергии и новой выплаты. Применяются существующие
  суммы наград каталога, а не новые клиентские расчёты.
- При чтении карты энергия не расходуется. Запуск оплачивается ровно один раз;
  продолжение/повтор не блокируются даже при нулевой энергии.
- При первом старте истории карта объясняет цель и правила до проверки энергии.
  Закрытие правил не создаёт назначения и не тратит дневную возможность.
- Родительские задания, парк и случайное событие Лиса не входят в эту тройку.

## Состояния и безопасность

`GET /quests/day` требует CHILD. Сервер под блокировкой профиля и активного дня
сохраняет снимок выбора, затем возвращает его. Отсутствие дня — пустой ответ,
не произвольный клиентский выбор. Повторные и одновременные запросы не меняют
выбор. `POST /quests/:id/start` проверяет снимок; прямой вызов не обходит карту.
Завершение перенесённого задания относится к текущему игровому дню. Выплата
остаётся через существующий ledger с прежним ключом идемпотентности assignment.

Старые завершения и выплаты не удаляются. Новая миграция убирает только связи
между разными персонажами и добавляет таблицы дневных предложений. Старые
незавершённые назначения подхватываются без новой оплаты энергией.

При нехватке свободных мест (например, сняты сапоги и осталось четыре просьбы)
сначала показываются старейшие невыполненные: оставшаяся просьба не удаляется,
а ждёт свободного места следующего дня. Это сохраняет лимит экономики.

## Границы

Это изменение карты/дневного допуска, а не редизайн мини-игр или изменение их
сценариев. У существующей игры сохраняется её единица задания: например, две
части истории Белочки пока относятся к одному серверному назначению.
Новый онбординг здесь не заменяется. Длительность восстановления энергии,
возраст кота, покупки и правила завершения дня не меняются.
Если все уровни персонажа закончились, он остаётся доступен для тренировки;
новая оплачиваемая копия старого задания не создаётся. При исчерпании каталога
просьб может быть меньше трёх — деньги за фиктивные задания не выдаются.

## Проверки

Между завершённым и новым днём карта показывает действие «Начать новый день».
Оно переводит домой и открывает новый день с планом распределения монет;
переход на карту сам по себе не создаёт день и не начисляет дневные деньги.
Для карты используется предоставленная `карта-четкая-v2.png` без повторного
масштабирования исходника (`assets/map/quest_map_hd.png`).

Фиксированный состав после перезахода; перенос и отсутствие пропуска уровня;
только один персонаж каждого вида; новая просьба только в новом игровом дне;
отказ прямому запуску вне списка; повтор/продолжение при энергии 0; повторная
отправка результата не выдаёт денег; конкурентные старты не тратят энергию дважды;
новый день без сети не генерирует новый награждаемый список на клиенте.
