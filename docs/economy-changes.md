# Рабочая экономика: изменения и проверка

Дата: 25 сентября 2026 года. Ветка: `feat/economy-app`.

## Главный экран и вкладка «Копилка»

В текущую ветку перенесён Flutter-интерфейс из ветки `mainscreen` без старых
версий backend, API и миграций. После онбординга открывается `MainShell` с
вкладками «Дом», «Карта», «Магазин» и «Копилка».

«Дом» показывает питомца, реальные балансы и план текущего дня. Вкладка
«Копилка» подключена к рабочей экономике и оформлена по отдельному референсу:
в ней есть баланс кошелька, текущая цель и прогресс, пополнение и возврат,
Сундук Морозко и быстрые действия. Все операции используют настоящий backend
и PostgreSQL, а не демонстрационные значения. «Карта» и «Магазин» пока остаются
заглушками из `mainscreen`.

Нужны запущенные PostgreSQL и backend, применённые существующие миграции до
`0020_onboarding_progress.sql` и загруженный `db/seed.sql`. Настройка описана в
корневом README и `backend/README.md`. Пароли задаются локально в `.env`.

После запуска сервисов:

```bash
flutter devices
flutter run -d <идентификатор-Android-эмулятора>
```

Android-эмулятор обращается к backend по адресу `http://10.0.2.2:3000`.
Отдельный релизный APK не требуется: Flutter сам собирает и устанавливает
debug-приложение. Web-конфигурация в эту публикацию не входит.

## Правила экономики

| Область | Поведение |
| --- | --- |
| Регистрация | Все кошельки создаются с нулём. Старое начисление 50 монет удалено. |
| Первый день | Выбор и подтверждение мечты → начисление 30 монет → составление плана. Закрытие выбора возвращает на экран без начисления денег. |
| Следующие дни | При начале нового игрового дня начисляется 30 монет. |
| План | Деньги распределяются между «Надо», «Хочу» и «Цель». При утверждении сумма категории «Цель» переводится в Копилку. |
| Обязательные расходы | Базовый резерв — 10 монет. Неиспользованную обязательную часть нельзя потратить на желания, перевести в Копилку или Морозко. |
| Копилка | Нужна выбранная цель. Пополнение сверх стоимости цели разрешено. Деньги можно вернуть в кошелёк с предупреждением о влиянии на прогресс. |
| Цель | Нельзя сменить, отменить или поставить на паузу до получения артефакта. Ограничения проверяются сервером. |
| Получение артефакта | Из Копилки списывается точная стоимость. Предмет появляется в инвентаре, автоматического надевания нет. |
| Следующая цель | Сразу открывается выбор следующей мечты. Остаток накоплений сохраняется. Полученные предметы исключаются из каталога. |
| Каталог исчерпан | Показывается сообщение, что все доступные артефакты получены. Дни доступны, но новое пополнение Копилки требует новой доступной цели. |
| Морозко | Один активный сундук; вклад из кошелька 10–50 монет шагом 10. Через пять завершённых игровых дней возвращается вклад и 10% в кошелёк. |
| Досрочное открытие | Возвращается вклад без бонуса. Подтверждение показывает вклад, прошедшие и оставшиеся дни, неполученный бонус и итоговый баланс. |

Серверная экономика также включает покупки для питомца, случайные события,
квестовые награды, родительские задания, финансовые цели, инвентарь и историю
завершённых дней. Каталог содержит квесты с наградами 10/12/15 и артефакты
стоимостью 80–150 монет. Морозко измеряет срок игровыми днями, не календарными.

## Подтверждения и ошибки

- Покупка: название, цена, категория «Надо»/«Хочу», баланс до и после,
  оставшийся обязательный резерв.
- Пополнение Копилки: сумма, кошелёк и накопления до/после, остаток до цели.
- Снятие: сумма, оба баланса, изменение расстояния до цели.
- Выбор мечты: предмет, стоимость, имеющиеся накопления и предупреждение
  о невозможности смены до получения.
- Получение артефакта: цена списания, остаток и сообщение об инвентаре.
- Морозко: подтверждения вклада, получения и досрочного возврата.

Отмена диалога не отправляет денежный запрос. На время подтверждения и отправки
повторные действия блокируются. Балансы перечитываются с backend; интерфейс
не устанавливает баланс самостоятельно. При отказе сервера состояние
обновляется и показывается понятная причина. При потере связи пользователь
получает указание проверить баланс перед повтором; автоматического повтора
денежной операции нет.

Недоступные покупки и переводы сопровождаются объяснением нехватки монет или
защищённого резерва. Контекстные действия ведут к заданиям, обязательным
покупкам, Копилке или выбору мечты. Сейчас они прокручивают временный экран.

## Исправления относительно предыдущего поведения

1. Убрано `50 + 30` при начале игры: регистрация больше не выдаёт стартовый бонус.
2. Выбор цели доступен до игрового дня: устранена зависимость от уже
   утверждённого бюджета.
3. Сервер запрещает замену незавершённой цели и повторное получение уже
   имеющегося артефакта. Конкурирующие изменения цели сериализуются.
4. После снятия накоплений достигнутая цель снова становится активной,
   если денег уже недостаточно. Получение повторно проверяет реальный баланс.
5. Повторный запрос получения артефакта не списывает деньги повторно.
6. Созревший Морозко возвращает вклад и бонус в основной кошелёк.
7. Отчёт дня считает переводы по стороне Копилки: две записи одного перевода
   больше не обнуляют сумму накоплений.
8. Проверки запуска Flutter обновлены: после онбординга ожидается экономика,
   а не старая заглушка.

## Подключение к `mainscreen`

Вся ветка `mainscreen` целиком не сливалась: это принесло бы устаревшие версии
серверных файлов. Перенесены только главный экран, нижняя навигация, модели и
виджеты питомца. Они адаптированы к единому `GET /economy/state`.

Денежные команды и описания подтверждений остаются в
`lib/economy/economy_actions.dart`, данные — в `economy_state.dart`, общий
диалог и сообщения — в `economy_action_ui.dart`. Новый экран Копилки вызывает
эти же команды, поэтому визуальная интеграция не дублирует финансовые правила.

Точки подключения:

| Блок главного экрана | Данные или действие |
| --- | --- |
| Баланс вверху | `EconomyState.wallet` — основной кошелёк |
| «Моя мечта» | Текущая цель, выбор первой/следующей цели и получение артефакта |
| «Составить план» | Выбор цели при необходимости, начало дня и утверждение бюджета |
| «Завершить день» | Серверная проверка обязательных расходов и результата дня |
| «Прогресс и подсказка» | План, результат и рекомендации |
| «Карта» | Переход к заданиям |
| «Магазин» | Покупки с подтверждением |
| «Копилка» | Подключена: накопления на мечту, возврат и отдельная механика Морозко |

`EconomyDestination` по-прежнему описывает смысл перехода, а не координаты
интерфейса. Полный временный `EconomyScreen` сохранён для разработки остальных
финансовых сценариев, но основной запуск теперь ведёт в `MainShell`.

## Ручная проверка

1. Для нового профиля проверить нулевой баланс после онбординга.
2. Нажать «Начать день», закрыть выбор мечты: доход не должен начислиться.
3. Повторить, выбрать и подтвердить цель: кошелёк получает 30 монет.
4. Утвердить план; проверить перевод запланированной суммы в Копилку.
5. Открыть подтверждение покупки, отменить: баланс не меняется. Повторить
   с подтверждением: деньги списываются один раз.
6. Проверить блокировку желания или перевода, затрагивающего обязательный резерв.
7. Пополнить Копилку и снять 5/10 монет: проверить подтверждения и прогресс.
8. Накопить стоимость цели с превышением, получить предмет: списывается только
   стоимость, остаток сохраняется, открывается следующий выбор.
9. Проверить Морозко: досрочный возврат без бонуса и получение с бонусом после
   пяти завершённых игровых дней. Оба возврата идут в кошелёк.
10. Проверить сохранение состояния после повторного открытия приложения.

## Выполненные проверки

- Flutter-анализатор: без замечаний.
- Функциональные тесты Flutter: экономика, запуск, API-клиент и онбординг
  прошли. Проверен переход из `MainShell` во вкладку «Копилка». Отдельно
  проверен диалог на 320×568 с масштабом текста 1,5.
- TypeScript typecheck, backend build и обычные backend-тесты прошли.
- Интеграционный тест на отдельной PostgreSQL 16 с ограниченной ролью
  `groshik_app` прошёл: выбор цели, резерв, отрицательные суммы, недостаток
  средств, повторные/конкурирующие запросы, остаток, пять дней Морозко,
  чужой сундук, отсутствие авторизации, родительская роль и сверка журнала.
- `git diff --check`: без ошибок.

Команды и переменная `ECONOMY_TEST_DATABASE_URL` для интеграционного теста
описаны в `backend/README.md`. Он создаёт тестовые данные и предназначен только
для отдельной базы. Старый вспомогательный тест генерации изображения
онбординга не входил в функциональный прогон. Главный экран и Копилка вручную
просмотрены на Android 16, API 36, эмуляторе `groshik_pixel`; найденное
переполнение списка целей исправлено прокруткой. Web в проекте не настроен,
поэтому `flutter build web` сообщает об отсутствии платформы `web`.

## База данных и публикация

Новых миграций нет. Изменён `db/seed.sql` с игровыми каталогами — его применение
обновляет соответствующие записи, поэтому это отдельный шаг настройки среды.

Удаление стартового бонуса действует для новых регистраций. Ранее созданные
профили автоматически не пересчитываются. В ходе локальной проверки у одного
тестового профиля была выполнена отдельная корректировка −50 с записью в журнал;
эта локальная операция не является миграцией и не повторяется при установке.

В GitHub публикуются исходники, документация и тесты. Локальные `.env`, токены,
база, изображения проверок и сборочные артефакты в коммит не включаются.
