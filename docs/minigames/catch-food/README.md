# «Лови корм»

Рабочая копия: `andromeda-catch-food`. Ветка расцветок: `codex/catch-food-all-coats`, база `06f48c5` из актуальной `main`. Исходная мини-игра уже включена в `main` через PR #8. По запросу пользователя комплект объединён с актуальной `main` после проверки совместимости. Отправка выполняется обычным fast-forward push с повторным получением `main` перед публикацией.

## Как открыть

В домике под карточкой мечты появилась карточка «Лови корм». Она доступна без активного дня и без незавершённых квестов. На первом экране видны управление, стоимость попытки, текущая сытость и рекорд. Просмотр инструкции бесплатный; ресурс списывается только после нажатия «Играть».

Используются все три расцветки питомца из игры: полосатая (`FUR_GRAY`), рыжая (`FUR_ORANGE`) и белая (`FUR_WHITE`). В мини-игре у всех общий красный ошейник; другие аксессуары не создают дополнительных комбинаций ассетов.

## Реализовано

- Четыре независимые дорожки; четыре фиксированные позиции миски.
- Движение по желобку и падение в миску за 2,4 секунды вместо 3 секунд; постепенное ускорение появления корма.
- Золотую рыбку нужно ловить. Испорченный круглый корм с красным крестиком нужно пропускать: пропуск безопасен, поимка добавляет одну ошибку без очков.
- Три ошибки (пропущенные рыбки или пойманный испорченный корм) завершают попытку; каждый кусочек учитывается один раз.
- Пауза, остановка при сворачивании приложения, ручное продолжение.
- Результат, личный рекорд, повторная попытка и возврат домой.
- Серверное списание сытости и сохранение результата для авторизованного ребёнка.
- Повтор запроса старта с тем же UUID не списывает ресурс повторно; повтор сохранения не изменяет уже записанный результат.
- Недостаточная сытость, отсутствие связи, повтор старта и повтор сохранения обрабатываются в интерфейсе.
- Домик обновляет состояние питомца после возврата.
- Точки окончания траекторий привязаны к координатам мисок в четырёх рисунках; задние лапы выровнены по общей опоре.
- 34 WebP (3 758 770 байт, ~3,58 МиБ): общий комплект и по восемь спрайтов для каждой из трёх расцветок. Исходные PNG, референсы, промпты и манифест включены в `art/minigames/catch_food/`. Экспорт повторяется командой `python tools/export_catch_food_assets.py` с Pillow.
- Кот в карточке входа, инструкции, всех четырёх игровых положениях и на результате соответствует `pet.fur_option_id`, который уже передаёт существующий API. Неизвестное или отсутствующее значение использует полосатого кота.
- Предзагружаются только восемь изображений выбранной расцветки и общие элементы. Если расцветка изменилась между открытием и стартом, новый комплект загружается перед запуском таймера.

Управление: четыре экранные кнопки; для клавиатуры Q/A — слева сверху/снизу, P/L — справа сверху/снизу, пробел — пауза/продолжение.

## Принятые допущения о балансе

Поскольку точные числа в исходном запросе не задавались:
- Стоимость попытки — текущая стоимость активности проекта: 20 единиц `energy_level`, отображаемых как сытость.
- Списание одноразовое, на сервере при старте. Пауза и сохранение результата не требуют дополнительных списаний.
- Усталость — предел **60 секунд активной игры** в одной попытке: «Бодр» → «Устаёт» → завершение с уставшим котом. Это состояние сессии, отдельная постоянная шкала не добавлялась.
- Перед следующей попыткой проверяется существующий запас энергии. Действует существующая система восстановления питомца.
- Пойманный корм — очки; он не создаёт еду в инвентаре и не увеличивает сытость. Монет и квестовых наград в этой игре нет.
- По запросу об ускорении и новом виде корма принято допущение о балансе: время движения 2400 мс, вероятность испорченного корма 20% со второго кусочка; первый всегда обычный. Окно ловли 180 мс и стоимость попытки сохранены. За испорченный корм нет дополнительного списания сытости.
- При закрытии процесса незавершённая попытка не восстанавливает движение корма. Уже подтверждённая стоимость старта сохраняется. После обычного выхода доступен экран результата.

Настройки хранятся в `backend/src/modules/catchFood/rules.ts` и передаются клиенту. При изменении максимальной длительности/лимита промахов также обновить ограничения таблицы отдельной миграцией.

## Сервер и миграция

Новая миграция: `db/migrations/0036_catch_food_sessions.sql`.
Она создаёт таблицу попыток, индекс рекордов и права существующей роли `groshik_app`.

Перед запуском новой версии backend нужны миграции из `db/migrations/`. Для локального просмотра 17 октября 2026 года миграция `0036_catch_food_sessions.sql` применена к существующей локальной БД `groshik` на localhost. Остальные миграции уже были применены. Backend запущен на `127.0.0.1:3000`, `/health` подтвердил готовность схемы, APK установлен в эмулятор `Medium_Phone`. Существующая локальная конфигурация загружена в окружение процесса; `.env` и секреты в эту рабочую копию не переносились.

Новые маршруты:
- `GET /minigames/catch-food` — конфигурация, питомец, рекорд.
- `POST /minigames/catch-food/start`, тело `{ "sessionId": "<UUID>" }`.
- `POST /minigames/catch-food/:sessionId/finish`, тело `{ "score": 0, "misses": 0, "elapsedMs": 0, "reason": "STOPPED" }`; причины также `MISSES` и `TIRED`.

Все маршруты требуют существующий bearer-токен и роль CHILD. Сервер проверяет принадлежность попытки, диапазоны, минимально возможное время для результата и число появившихся предметов. Рекорд предназначен для самого ребёнка, соревновательного рейтинга нет.

Новый backend откажется сообщать готовность через `/health`, пока миграция не применена.
