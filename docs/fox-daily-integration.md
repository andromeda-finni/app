# Лис в обычной игре

Основа изменений: актуальная GitHub `main`, коммит `06f48c5`.
SHA сверен через `git ls-remote origin refs/heads/main`; локальная ссылка обновлена
явным `git fetch origin +refs/heads/main:refs/remotes/origin/main`.
В репозитории fetch refspec настроен только на другую ветку, поэтому простой
`git fetch origin main` обновляет `FETCH_HEAD`, но не гарантирует обновление `origin/main`.

Лис приходит в дом как случайное событие с вероятностью **70% за игровой день**.
Он не является точкой карты. Карта `assets/map/quest_map_squirrel.webp` содержит
Белочку и остаётся без изменений. Её исходное разрешение — 548×1280; новый
файл большего разрешения пользователь предоставит отдельно.

## Поведение

- `POST /fox-events/visit` сохраняет и успешный, и неуспешный розыгрыш.
  Перезапуск приложения, обновление дома и повторный запрос не дают нового шанса.
- Незавершённый разговор сохраняется на сервере; в доме доступна кнопка продолжения.
- Сценарный возврат на следующий игровой день имеет приоритет над новым розыгрышем.
  В этот день дополнительный новый визит не создаётся.
- Используются все пять существующих историй и существующее соответствие сложности:
  `SIMPLE` → младшая линия, `ADVANCED` → старшая. Истории идут по авторскому порядку.
- `POST /fox-events/advance` принимает идентификаторы визита, текущего узла и ответа.
  Сервер проверяет переход и определяет сумму сам. Изменение баланса и прогресса
  фиксируются одной транзакцией; повторы не списывают и не возвращают монеты дважды.
- Расходуется только `SPENDABLE`, с сохранением существующего резерва на питомца.
  Целевые накопления не расходуются.

**Assumption:** визит показывается после завершения обучения и утверждения плана дня,
когда активна вкладка дома. Отложенный возврат следует существующим сценариям и
происходит гарантированно, а не по новому случайному броску.

При отсутствии связи розыгрыш и денежные ответы не исполняются локально.
Прогресс остаётся на сервере; ребёнок может повторить ответ или вернуться в дом
после восстановления связи. Существующая офлайн-экономика продолжает работать.

## Подключение

Основной `lib/main.dart` всегда запускает полную игру. Устаревший флаг
`FOX_EVENT_DEMO` больше не подменяет её отдельным демоэкраном. Изолированный
просмотр историй доступен разработчикам только через явный запуск
`flutter run -t lib/main_fox_preview.dart`.

Перед запуском обновлённого backend применить стандартным механизмом проекта
миграцию `db/migrations/0036_fox_daily_events.sql`. Она добавляет хранилище состояния
и тип операции `FOX_EVENT`; `/health` требует эту миграцию. Новых зависимостей нет.

Правила переходов backend экспортируются из авторских Dart-сценариев:

```powershell
dart tool/export_fox_rules.dart
```

Тест `test/fox_event_service_test.dart` проверяет полное совпадение экспорта
с исходными историями, включая суммы, ожидание и все варианты ответов.

